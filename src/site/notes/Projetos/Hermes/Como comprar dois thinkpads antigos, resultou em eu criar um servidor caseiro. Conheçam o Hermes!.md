##### Configurando o Debian Server

Agora nós estamos oficialmente com o servidor, ele ainda está na planta mas ele existe. Primeira coisa que fiz foi vê se tinha algo para atualizar, então rodei um *apt update*, depois disso, rodei *ip addr*, para descobrir o ip do servidor.

![PICT0077.jpg](/img/user/imgs/PICT0077.jpg)
*(e ele disse "haja terminal, e houve terminal")*


Talvez aqui foi onde encontrei o maior problema que o servidor pode passar a longo prazo. Para explicar qual o problema e o porquê disso, vou explicar mais ou menos o que é DHCP e como um roteador distribui IPs. *(ou como eu acho que é, pelo ou menos)*

Você, na sua casa, tem vários aparelhos que se conectam a sua rede através do roteador, e ele tem um protocolo chamado **DHCP**, esse protocolo é responsável por **distribuir os endereços de ip de maneira automática na rede da sua casa**, ou seja, seu celular vai receber um, seu pc outro e assim sucessivamente, mas como isso é feito de maneira automática, o ip dado para um aparelho pode mudar se assim o roteador decidir. Para resolver isso seria necessário entrar no painel do roteador e separar um endereço de ip especifico para o meu servidor, porém eu não tenho acesso a esse painel e nem posso, pois minha provedora de internet não permite, portanto a solução que encontrei foi achar uma porta que não tivesse nada conectado e colocar meu servidor lá, porém como não modifiquei isso diretamente no roteador, nada o impede de em um dia qualquer ele dar esse endereço para outro dispositivo e o ip do meu servidor mudar e eu ter que reconfigurar algumas coisas novamente. Então, basicamente estamos rodando em fé e esperança que meu roteador não vai fazer uma trollagi do zoio.

Mas com isso do IP deixado para trás, chegou a hora de configurar o ssh para que eu consiga acessar o servidor através do meu desktop ou até do meu outro thinkpad. A única coisa que precisei fazer foi ligar o openssh do meu servidor e pronto, já era possível acessar o meu servidor através do meu desktop pelo cmd.

Depois disso para finalmente deixar o x200 quietinho, tive que configurar ele para que ao fechar a tampa ele não desligasse, para fazer isso só tive que mudar essas três configurações abaixo de suspend para ignore.

`HandleLidSwitch=ignore`
`HandleLidSwitchExternalPower=ignore`
`HandleLidSwitchDocked=ignore`

#### Instalando os serviços

**NEXTCLOUD e TAILSCALE**

O primeiro serviço que quis instalar foi o nextcloud, porque quero guardar arquivos em um lugar que não me limite igual o google drive e que garante privacidade.

Eu pensei que seria fácil, porém **DEMOROU MUITO**, o nextcloud estava dando problema, eu não conseguia criar uma conta, para criar era necessário colocar um banco de dados, eu fui usar o MariaDB e simplesmente ele não tava funcionando no docker, demorei muito tempo e, depois de muito papo com o gepeto, finalmente o nextcloud estava funcional, eu nunca tomei tanto gap como agora.

No fim, acabei tendo que desistir do nextcloud, ele estava ocupando 100% da CPU mesmo sem rodar nada nele, então, obviamente estava inutilizável. Portanto, decidi ir para uma alternativa mais leve, decidi usar o file browser, ele funciona igual o nextcloud mas tem menos funções, mas para meu objetivo ele serviu.

Com o file browser configurado, era hora de configurar o tailscale, ele é que vai permiti a gente conectar no servidor de fora da nossa rede local, assim vou conseguir acessar o servidor quando estiver fora de casa e no caso do server de minecraft e outro serviços que quero compartilhar com pessoas, ele vai ser necessário para que elas consigam acessar algumas portas do meu servidor.

Configurar o tailscale foi tranquilo também, sem problemas.


**SERVER DE MINECRAFT**

Para o servidor de minecraft eu instalei o *itzg/minecraft-server*, é uma imagem do docker que já configura um servidor de mine de maneira automática, como estou usando um notebook antigo, decidi rodar o server numa versão antiga, então o servidor está rodando no minecraft 1.8.9 vanilla, sinceramente, é minha versão favorita do mine e nem ligo de estar jogando nela, configurei para que o server ocupasse no máximo 1.25gb de ram.

Basicamente foi só rodar esse comando abaixo e pronto, meu server estava rodando na porta 25565.

~~~ bash
docker run -d \
  --name minecraft \
  --restart unless-stopped \
  -p 25565:25565 \
  -e EULA=TRUE \
  -e TYPE=VANILLA \
  -e VERSION=1.8.9 \
  -e MEMORY=1.25G \
  -v /srv/minecraft:/data \
  itzg/minecraft-server:java8
~~~

Agora o que faltava era configurar para que através do tailscale meus amigos conseguissem jogar junto comigo, a grande questão aqui é que para isso tenho que adicionar eles a minha rede, porém isso significa que eles terão acesso a tudo do meu servidor, o que não é meu objetivo, portanto tive que configurar ACLs no meu tailscale, para que os meus amigos só consigam ver o server do mine ao se conectar a minha tailnet, os outros serviços fiquem inacessíveis.

Para isso tive que reconfigurar as Grants, criei uma regra para que somente o owner, no caso eu, pudesse acessar todas as portas, já para todas as pessoas que entram após mim, eles automaticamente são limitados pelo tailscale e somente a porta do server é que fica acessivel para eles. Com isso, agora era hora de testar se o servidor aguentava muita gente. 

O teste foi um sucesso, o máximo de CPU consumida foi 48%

**SERVER DE CS:SOURCE**

Primeiramente, por óbvia limitações de hardware, eu tenho uma regra comigo mesmo de que: **ou o servidor de minecraft fica rodando ou o de cs source**, meu plano é deixar o server de minecraft aberto 24/7 e o de cs:source abrir só quando eu e meus amigos formos jogar realmente, com isso sempre que o server de cs abrir, o de mine se fecha e vice versa, pretendo automatizar isso, mas antes preciso fazer o server de cs:source funcionar.

Para fazer o server de cs foi o mesmo esquema, fiz pull de uma imagem do docker  que configura um server de cs source, estranhamente achei até bem igual ao do minecraft, a única coisa que mudou foi que eu e meus amigos costumamos jogar com os mapas do cs:go, então para isso tive que upar os mapas no meu file browser e dele fazer um copypaste para o container que tinha meu server de cs, foi bem fácil, o único erro que estava enfrentando era problema de permissão da pasta onde os mapas estavam, mas depois que coloquei as permissões na pasta, o servidor começou a conseguir acessa-la e tudo funcionou perfeitamente, então para adicionar os mapas na rotação do servidor eu coloco o nome deles num arquivo chamado *map_cycle.txt*, com isso quando formos jogar, não precisamos ficar mudando manualmente, só se quisermos, para mudar o mapa é só rodar um comando no console do próprio jogo.

Então assim estava aberto mais um serviço do meu servidor: **o server de cs:source**

**JELLYFIN**

Com o server de mine, de cs e o sistema de arquivos funcionando, agora chegou a hora de ajustar o jellyfin, sendo esse o ultimo serviço que pretendo colocar no meu servidor no momento.

O jellyfin é um programa onde podemos colocar arquivos de mídia, como filmes, séries, músicas e livros, e através dele fazer a reprodução desses arquivos.

Eu não vou explicar como foi para instalar, porque foi basicamente igual ao servers de mine e cs, só foi puxar um container e configurar algumas nuances dele.

O grande ponto aqui foi como fiz para acessar, esses filmes e etc. Tudo o que precisei fazer foi criar uma pasta dentro do file browser, onde lá eu upo os filmes através do meu pc ou outro dispositivo, o jellyfin scaneia essas pastas e exibe os arquivos deixando eles prontos para a gente só assistir.

![Pasted image 20261010035940.png](/img/user/imgs/Pasted%20image%2020261010035940.png)
*(séries que adicionei no jellyfin)*

O grande problema que eu enfrentei foi a questão de *transcoding*, que é basicamente quando para exibir uma mídia, o dispositivo faz a transcodificação dela, por exemplo um filme em 2k e .mkv, que através do *transcoding* fica em 1080p e .mp4 para rodar em um dispositivo especifico. Se meu servidor tivesse mais cpu e ram, esse processo seria simples, mas como estou usando um notebook de 2008, fazer esse processo no lado do servidor é muito custoso, quando tentei rodar filme com transcoding ativado, o jellyfin consumiu **80% da cpu** e muita ram.

Para contornar isso tive que primeiramente desativar o transcoding no jellyfin, ou seja, se for depender de transcoding ele não vai exibir o filme/série, isso pode ser um problema, por exemplo, quando desativei o transcoding e fui tentar ver o filme que eu havia adicionado novamente,  o filme não carregava, ficava no loading infinito, mas eu descobri que para contornar isso, as pessoas usam front-ends específicos onde você conecta seu jellyfin e esse front-end que você usa fica responsável pela transcodificação, com isso, foi possivel rodar filmes e séries sem consumir nada da cpu e da ram é como se meu servidor só estivesse entregando o arquivo e o cliente que se vire para exibir esse arquivo. 

Para assistir filmes e séries no pc usei o programa proprio do jellyfin (Jellyfin Media Player) e no android usei findroid.

Agora, a parte que mais achei daora do jellyfin foi fazer stream de musicas através do servidor, o esquema é o mesmo dos filmes/séries, mas aqui é especial, porque posso usar players diferentes de música. Eu costumo usar o youtube music, então fiz um script em python (você pode encontrar [aqui](https://github.com/ThiagoPeixoto81/playlist-converter), caso te interesse) para converter e baixar essas músicas dessas playlists, além de adicionar metadados nelas se possível, a questão de pegar metadados de músicas do youtube music sempre é meio ruim, porque as vezes as musicas se misturam com vídeos e os metadados não chegam da maneira certa, então boa parte tive que ajeitar na mão mesmo, mas o resultado valeu a pena, ficou muito daora. 
Como front para ouvir músicas direto do meu jellyfin no pc estou usando o **feishin** e no celular estou usando **finamp**.
